## 1. Epic Objective

Generate every variant the UI needs and extract metadata without ever modifying the original.

---

## 2. Business Value

Blueprint §12.3 explains why the timeline can feel instant offline: blurhash and thumbnails are tiny and aggressively cached. This epic produces them.

---

## 3. User Stories

> **As a** user on a slow connection
> **I want** photos to appear instantly even before they load
> **So that** browsing my archive never feels like waiting

---

## 4. Functional Requirements

- Image variants in AVIF/WebP/JPEG at four widths
- Blurhash
- Video HLS ladder and poster frame
- Audio AAC and waveform
- EXIF with GPS stripped

---

## 5. Technical Requirements

- sharp for images, FFmpeg for video and audio
- Isolated container
- `transcode_status` state machine with failure surfaced to the UI

---

## 6. UI Requirements

_Not applicable._

## 7. API Requirements

_No new API surface in this epic._

## 8. Database Requirements

- Updates variant keys, blurhash, exif, and status on `media_assets`

---

## 9. Security Requirements

- Non-root, no DB credentials, no egress beyond storage
- GPS stripped by default

---

## 10. Testing Requirements

- Corrupt file, oversized file, rotation, HDR, HEIC, failure surfacing
