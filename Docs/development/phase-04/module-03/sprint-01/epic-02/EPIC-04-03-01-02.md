## 1. Epic Objective

Serve media only through short-lived signed URLs, and render it progressively.

---

## 2. Business Value

Blueprint §12.5: "buckets are entirely private. Access is always via short-TTL signed URLs, minted only after an authorisation check." This is the epic that makes that true in practice.

---

## 3. User Stories

> **As a** user
> **I want** certainty that a leaked link cannot expose my archive
> **So that** sharing one memory does not risk all of them

---

## 4. Functional Requirements

- Signed-URL endpoint with authz and rate limits
- Progressive image component
- Adaptive HLS video component
- Audio player with waveform

---

## 5. Technical Requirements

- Five-minute view TTL, sixty-minute download TTL
- Per-user minting limits
- Graceful expiry handling in components

---

## 6. UI Requirements

- blurhash → thumb → preview → original progression (§12.3)
- `Save-Data` awareness

---

## 7. API Requirements

_No new API surface in this epic._

## 9. Security Requirements

- Authz before minting
- Rate limits
- No enumerable structure
- Hotlink protection

---

## 10. Testing Requirements
