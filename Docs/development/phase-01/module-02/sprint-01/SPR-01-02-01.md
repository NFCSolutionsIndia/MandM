## 1. Sprint Goal

A developer can build any Release 1 screen using only existing primitives and tokens, in either theme, without writing a raw colour value.

---

## 2. Scope

### In Scope

- Token stylesheet and Tailwind preset
- Font loading
- Twelve primitives
- Skeleton/empty/error templates
- Theme provider and toggle
- Configuration-driven app shell

### Out of Scope

- Any product screen
- Feature-specific components
- Marketing site design (PHASE-10)

---

## 3. Technical Approach

- Tokens as CSS custom properties consumed through a Tailwind v4 preset, so a component never contains a hex value.
- Radix primitives as the behavioural base; styling is ours, accessibility is theirs.
- Build the shell as configuration so the Release 3 navigation change (Timeline → Gifts) is a config edit, not a rewrite (gap analysis §3 item 3).

---

## 4. Architecture Changes

- Establishes the theming contract in ADR-014 that every later component depends on.
