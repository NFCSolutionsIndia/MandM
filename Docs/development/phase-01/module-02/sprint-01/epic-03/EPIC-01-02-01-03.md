## 1. Epic Objective

Build the configuration-driven responsive shell: bottom tab bar on mobile, sidebar on desktop.

---

## 2. Business Value

Navigation is the frame every screen lives in. Making it configuration-driven means the planned Release 3 change — Timeline giving up its tab to Gifts — is a config edit and an announcement, not a refactor.

---

## 3. User Stories

> **As a** mobile user
> **I want** the main actions within reach of my thumb
> **So that** I can use the app one-handed while holding a child

> **As a** desktop user
> **I want** a persistent sidebar and keyboard shortcuts
> **So that** I can work through a large archive efficiently

---

## 4. Functional Requirements

- Mobile: five-item bottom tab bar with a raised centre create action.
- Tablet: tab bar in portrait, icon rail in landscape.
- Desktop: persistent sidebar plus a top command bar with global search.
- Tab bar hides on scroll down, returns on scroll up.
- Safe-area insets honoured.

---

## 5. Technical Requirements

- Navigation defined as a configuration array with release gating, so items can be added or swapped without touching layout code.
- Active state derived from the route, with the filled icon variant for the active tab (§26.6).
- The centre create action opens a sheet, not a route — context is never lost (§28.1).

---

## 6. UI Requirements

- §28.1 structure: Home · Occasions · (+) · Timeline · Me
- Filled icons for active state
- ≥44×44px targets
- Scroll-away behaviour

## 12. Epic Acceptance Criteria

- [x] Shell renders correctly at all three breakpoints
- [x] Navigation is configuration-driven
- [x] Keyboard and screen-reader operable

Verified 2026-09-03 at four real viewport sizes in Chromium — 390×844, 834×1112,
844×390 and 1440×900 — plus 177 unit tests and 60 end-to-end tests. axe is clean
at all three breakpoints and with the create sheet open, every navigation target
clears 44×44, and every stop in a keyboard traversal carries a visible focus ring.

The configuration claim was demonstrated literally: `CURRENT_RELEASE` was set to
3, the app was rebuilt, and the bar read `Home · Occasions · Create · Gifts · Me`
with no component edited. Reverted, and the same demonstration is now a test.

**What a real browser caught that review and jsdom did not:**

- `md:landscape:` also matches a desktop monitor, and Tailwind emits it after
  the `lg:` rules — so the icon rail rendered beside the sidebar at 1440px
- the command bar was inset for the sidebar and not for the rail, so the
  wordmark read "s & Memories" underneath it at 844×390 (found in a screenshot,
  not by a test — no assertion measured it, and axe has no opinion about a word
  being covered by a panel)
- `(app)/error.tsx` did not exist, so a failing route escaped to the root
  boundary and replaced the whole screen — the opposite of §14
- `main` added the safe-area inset that `body` already reserved, double-counting
  it, and the toast layer offset itself by 4rem against a 3.5rem bar

**The epic is `progress`, not `completed`**, for one TASK-016 §17 criterion:
safe-area insets have not been seen on real hardware. `env(safe-area-inset-bottom)`
is 0px in every desktop browser, so the insets are now read once into
`--safe-bottom` (globals.css) and the behaviour is proven with a forced 34px
value — the bar grows by exactly that, stays anchored to the bottom, still clears
the last row, and adds nothing at all when the inset is zero. What remains is an
iPhone.
