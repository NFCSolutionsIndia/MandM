## 1. Epic Objective

Implement the §26 token system correctly in all three theme states, avoiding the bug present in the existing repository.

---

## 2. Business Value

Theming done wrong is visible on every screen and expensive to fix later. The existing repo demonstrates the exact failure: its dark mode sets `--primary` to pure white, so the brand colour vanishes in dark mode.

---

## 3. User Stories

> **As a** user with dark mode enabled
> **I want** the app to respect my system theme and still look like itself
> **So that** it feels considered rather than inverted

---

## 4. Functional Requirements

- Light, dark, and system themes
- A user-facing override that wins in both directions
- No flash of unstyled or wrong-theme content

---

## 5. Technical Requirements

- Complete light palette on bare `:root`.
- Only changed tokens redefined under `@media (prefers-color-scheme: dark)` guarded as `:root:not([data-theme="light"])`.
- Same tokens redefined under `:root[data-theme="dark"]` so an explicit choice wins.
- Theme preference persisted and applied before first paint.

---

## 6. UI Requirements

- Every colour, radius, shadow, spacing step, and motion duration from §26.3–26.5 exposed as a token

---

## 7. API Requirements

_No new API surface in this epic._

---

## 8. Database Requirements

_No schema changes._

---

## 9. Security Requirements

- Theme preference in `localStorage` only; wrapped in try/catch since a private window can throw on access

---

## 10. Testing Requirements

- Render in all three states
- Assert no token is defined only inside a media query
- Contrast assertions for the coral small-text rule
