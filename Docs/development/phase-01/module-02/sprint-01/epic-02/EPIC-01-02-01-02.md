## 1. Epic Objective

Build the twelve primitives every Release 1 screen needs, accessible and themed, with all documented states.

---

## 2. Business Value

Twelve components built once, correctly, replace dozens built inconsistently. Accessibility built into the primitive means every screen inherits it rather than being audited into compliance.

---

## 3. User Stories

> **As a** user relying on a screen reader
> **I want** every control to announce what it is and what it does
> **So that** I can use the product independently

---

## 4. Functional Requirements

- Buttons in five variants × five states.
- Inputs in six states including async-checking.
- Bottom sheet, dialog, toast, undo snackbar.
- Chips, avatars, status chips, progress (bar/ring/upload).
- Skeleton, empty, and error templates.

---

## 5. Technical Requirements

- Radix primitives underneath for focus management, dismissal, and ARIA.
- Focus moves into a sheet or dialog on open, is trapped, and returns to the trigger on close (§33.17).
- Every component consumes tokens only.

---

## 6. UI Requirements

- All states in both themes
- Reduced-motion variants
- ≥44×44px targets
- Visible focus ring

## 12. Epic Acceptance Criteria

- [x] Twelve primitives complete with documented states
- [x] Keyboard and screen-reader operable
- [x] axe clean

Verified 2026-09-02. Every primitive is rendered in every documented state at
`/design/components`, in both themes, and the accessibility suite
(`apps/site/e2e/a11y.spec.ts`) runs axe against that page and against
`/design` in light and dark, with the sheet open, the confirmation open, a
toast visible and a field in error — a closed dialog is not in the DOM, and an
axe pass that never opened one has not tested it.

Three checks are asserted by hand because no rule can express them: a visible
focus indicator on every one of 25 tab stops, a 44×44 minimum on every
interactive target (WCAG 2.2 asks for 24×24; §26.8 commits to 44), and the
skeleton reserving exactly the height its loaded content takes.

**What the gate caught, none of which review or the jsdom suite had found:**

- every primitive cancelled the global focus ring with
  `focus-visible:outline-none` and put nothing back — the whole library was
  keyboard-invisible
- `--text-tertiary` (§26.3, #9C9793) is 2.75:1 — the colour of every
  placeholder and every piece of metadata in the product, below AA
- `--success`, `--error`, `--warning` and `--info` all fail as text; white on
  the destructive button was 4.13:1
- `Countdown` computed a relative time during the server render, so hydration
  failed and React discarded the `data-theme` attribute — a user who chose
  dark was silently returned to light
- a confirmation opened inside a sheet dropped focus to `document.body` on
  Escape
- `SkeletonRegion` carried an `aria-label` on a plain `<div>`, which ARIA
  discards, so the loading state announced nothing

The palette corrections are recorded in `apps/site/src/styles/tokens.css` and
guarded by `src/styles/__tests__/tokens.test.ts`, which measures every text
token against every surface in both themes rather than repeating hex values.
