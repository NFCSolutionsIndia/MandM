## 1. Sprint Goal

A developer can author a schema change, generate a migration, apply it, roll it back, and seed realistic data — and no table can be added without an scope enforcement.

---

## 2. Scope

### In Scope

- `packages/db` with Drizzle configuration, client, schema directory, and migration directory.
- Initial migration establishing the database conventions, enums from `@mm/shared` as `CHECK` constraints, and the scope convention.
- Seed script with realistic content.
- Migration test harness.

### Out of Scope

- Domain tables (PHASE-02 and PHASE-03 own theirs)
- Query helpers (they belong to feature modules)

---

## 3. Technical Approach

- Drizzle schema is the source; migrations are generated and committed, never hand-edited after review.
- Set `UTF-8` / `ICU collation` schema-wide in the first migration and declare the sanctioned column helpers; no extensions exist to enable. Semantic search is OpenSearch at R2 (ADR-010).
- Establish the scope convention with a template and guard test, so PHASE-02 inherits it rather than inventing it.

---

## 4. Architecture Changes

- Introduces `packages/db` as the single schema source consumed by both apps (ADR-005).
