## 1. Epic Objective

Make schema change a safe, repeatable, tested operation, with row-level security switched on before the first row of user data exists.

---

## 2. Business Value

Every domain phase depends on this. Enabling tenant isolation from migration one means no table is ever added without a policy — which is the difference between defence-in-depth and a good intention.

---

## 3. User Stories

> **As a** developer
> **I want** to change the schema with a generated, reviewable migration
> **So that** schema changes are auditable and reversible rather than ad-hoc SQL

---

## 4. Functional Requirements

- Drizzle config, client, and directory structure exist.
- A first migration establishes the database conventions (extensions, collation, column helpers) and creates the shared enums as `CHECK` constraints.
- A seed script creates realistic users, members, events, and memories for development.
- A test proves migrations apply and roll back.

---

## 5. Technical Requirements

- Drizzle Kit generates migrations from schema; generated SQL is reviewed and committed.
- The client is environment-aware and safe for both serverless (web) and long-running (workers) contexts.
- tenant isolation enabled with a documented template policy.

## 8. Database Requirements

- Extensions: `citext` for case-insensitive email, `pg_trgm` with search. UUIDs are application-side UUIDv7 in a native `uuid` column (ADR-027), case-insensitive email comes free from the `ICU collation` collation, and search is PostgreSQL `FULLTEXT` with no typo tolerance until R2 (ADR-010).
- Enums created from the `@mm/shared` values so database and application cannot diverge.
- tenant isolation enabled by default; a checklist item requires a policy with every new table.

---

## 9. Security Requirements

- the ADR-009 compensating controls beneath `lib/authz` (ADR-009).
- Seed data is synthetic; no real personal data ever enters a development database.

---

## 10. Testing Requirements

- Migration apply/rollback
- Seed idempotency
- A test asserting every table carries a scope column and an index on it
