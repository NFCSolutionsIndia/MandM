## 1. Epic Objective

Every push is typechecked, linted, tested, built, and deployed to an isolated preview with its own database; errors from both apps reach Sentry.

---

## 2. Business Value

Preview-per-PR lets product and design review real behaviour continuously instead of at the end of a phase. Error tracking from day one means the first production bug is diagnosable rather than a mystery.

---

## 3. User Stories

> **As a** developer
> **I want** every pull request to produce a working preview with its own data
> **So that** I can demonstrate and review real behaviour without touching production

---

## 4. Functional Requirements

- CI runs typecheck, lint, test, and build on every push and blocks merge on failure.
- Each pull request gets a preview deployment and an isolated Aurora PostgreSQL database branch.
- Workers deploys to AWS ECS Fargate on merge to `main`.
- Uncaught errors from both apps appear in Sentry with source maps and release tagging.

---

## 5. Technical Requirements

- GitHub Actions with pnpm and Turborepo remote caching.
- Aurora preview schema created on PR open and destroyed on close.
- Environment-scoped secrets; no production credentials available to preview builds.
- Sentry release created per deploy, with source-map upload.

## 9. Security Requirements

- Secret scanning enabled in CI.
- Dependency audit runs on every PR and fails on a known critical advisory.
- Preview environments never receive production database or storage credentials.

---

## 10. Testing Requirements

- A deliberately broken PR proves each CI gate blocks
- A thrown error in each app proves Sentry ingestion
