## 1. Epic Objective

Configure the background sync layer and build the offline read layer.

---

## 2. Business Value

Blueprint §12.3 explains why this works at all: blurhash and thumbnails are tiny, so a useful offline archive fits comfortably in a cache.

---

## 3. User Stories

> **As a** user on a plane
> **I want** to browse my recent memories
> **So that** the archive is with me, not just on a server

---

## 4. Functional Requirements

- Precached shell
- Per-class runtime caching
- Thumbnail LRU with a cap
- Offline reads from the on-device store
- Marked uncached ranges
- Offline fallback page
- Update prompt

---

## 5. Technical Requirements

- WorkManager / URLSession
- Network-first for authenticated GETs
- Cache-first for immutable derivatives
- ~200MB LRU honouring `storage.estimate()`

---

## 6. UI Requirements

- Offline banner; uncached ranges marked (§29.12)

---

## 7. API Requirements

_No new API surface in this epic._

---

## 8. Database Requirements

_No schema changes._

---

## 9. Security Requirements

- No authenticated response cached beyond its class; no tokens in caches

---

## 10. Testing Requirements
