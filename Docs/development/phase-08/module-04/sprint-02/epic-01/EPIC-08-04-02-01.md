## 1. Epic Objective

Build the Release-1 operator console with a hard content boundary.

---

## 2. Business Value

Blueprint §31.2 calls delivery health "the most important internal screen in the company". §16.3 makes the access model unusually strict, and correctly so.

---

## 3. User Stories

> **As a** operator
> **I want** to know immediately if a capsule missed its delivery
> **So that** we can fix it before the user notices

> **As a** support agent
> **I want** to help a user without seeing their private memories
> **So that** I can do my job without holding power I should not have

---

## 4. Functional Requirements

- Admin auth with mandatory TOTP and backup codes
- Delivery health with due, failed, at-risk, and channel rates
- Job queue with stuck detection and manual re-run
- User lookup without content
- Break-glass with reason, second approver, and user notification
- System health
- Audit viewer

---

## 5. Technical Requirements

- Separate subdomain, independent rate limits, 30-minute session timeout
- Role separation with support having no content access
- Watchdog alert wired to paging

## 9. Security Requirements

- Hardware MFA
- No content by default
- Break-glass audited and notified
- IP allowlisting

## 10. Testing Requirements
