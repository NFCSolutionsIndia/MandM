## 1. Module Objective

Turn the product's privacy claims into surfaces the user can inspect and controls they can use.

---

## 2. Business Requirements

- Blueprint §24.1: "Demonstrated control beats claimed encryption — and it is honest, which the current copy is not quite."

---

## 3. Functional Requirements

- Audit log written on every content access
- User-visible access log
- Active-link management
- WebAuthn app lock
- Vault PIN
- Default visibility setting

---

## 4. User Flows

_Not applicable to this module._

## 5. UI/UX Requirements

- Privacy settings per §29.10
- App lock screen per §29.28

---

## 6. Backend Requirements

- Audit writes across every sensitive path
- App lock re-verification

---

## 7. Database Requirements

- `audit_log`, append-only, 24-month retention

---

## 8. Integration Requirements

_No external integrations._

---

## 9. Security Requirements

- Every content access logged
- Admin access always logged and notified
- App lock uses the PHASE-02 WebAuthn primitive

---

## 10. Testing Requirements

- Audit coverage across paths
- App lock timeout
- Log visibility scoping
