## 1. Sprint Goal

A session can be created, validated, listed, and revoked; OTP codes can be issued and verified safely; abuse is rate-limited.

---

## 2. Scope

### In Scope

- Auth schema and migration scoped through `lib/authz`
- Session service
- OTP service
- Rate-limit service
- Step-up re-auth primitive

### Out of Scope

- Any UI (next sprint)
- Passkeys and OAuth (next sprint)
- Vault and authz (MOD-02-02)

---

## 3. Technical Approach

- Model sessions as rows, not tokens carrying claims, so revocation needs no blocklist (ADR-008).
- Hash everything that functions as a bearer secret: session tokens, OTP codes, recovery codes.
- Rate limiting in the database for Release 1 (ADR-011); the interface is written so an edge or Redis implementation can replace it without touching callers.

---

## 4. Architecture Changes

- Introduces the session contract consumed by every later request
- Introduces the rate-limit interface used by upload, share, and seal endpoints later
