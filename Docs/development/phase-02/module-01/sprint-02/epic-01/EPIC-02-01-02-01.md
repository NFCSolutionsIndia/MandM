## 1. Epic Objective

Build the four authentication screens to the specification in blueprint §29.3–29.6.

---

## 2. Business Value

This is the first thing anyone sees after the landing page. It sets the expectation for how careful the rest of the product is.

---

## 3. User Stories

> **As a** new user
> **I want** to create an account with just my email
> **So that** I can start without inventing another password

> **As a** returning user
> **I want** to get in with one tap
> **So that** the app does not tax me for coming back

---

## 4. Functional Requirements

- Signup: name, email, phone with country picker, terms checkbox, social options.
- Dual verification: phone code then email link, with a documented "verify later" state.
- Login: email or mobile, passkey quick-login, non-enumerating errors.
- Forgot/reset: always the same success message; expired-token state.

---

## 5. Technical Requirements

- Server actions returning the ADR-023 result union so forms render field-level errors without a boundary.
- Region auto-detected for the phone country picker.
- Async uniqueness check on email with the inline spinner-then-tick pattern.

---

## 6. UI Requirements

- All four screens per §29.3–29.6 with five states each, both themes
- Confetti moment on verification success (§29.4)
- Amber "verify email to unlock scheduling" banner

---

## 9. Security Requirements

- Non-enumerating copy
- Rate-limit feedback with a live countdown
- Terms acceptance recorded with a timestamp and version
