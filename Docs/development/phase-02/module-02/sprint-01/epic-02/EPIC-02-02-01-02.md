## 1. Epic Objective

Build the single authorization module, encode the blueprint §11.2 permission matrix as executable data, and generate a test per cell.

---

## 2. Business Value

This is the module that prevents the product-ending failure. Its value is measured in the incident that never happens.

---

## 3. User Stories

> **As a** user
> **I want** certainty that no other user can reach my vault
> **So that** I can put my family's history here without reservation

---

## 4. Functional Requirements

- One `authorize({ subject, action, resource })` entry point returning allow or deny with a reason.
- Grant sources: vault membership now; share link and delivered capsule recipient as declared-but-empty branches for PHASE-05.
- Route guards for the authenticated group.
- Step-up re-authentication required for the capabilities blueprint §20.1 lists.

---

## 5. Technical Requirements

- The matrix lives as data; the runtime check and the test suite are both derived from it, so they cannot diverge.
- Deny by default: an unknown action or resource type denies.
- Denial reasons are structured for audit logging.

## 9. Security Requirements

- Client-supplied ids are filters, never authorization
- Every query scoped by a session-derived vault id
- A failing matrix cell fails CI

---

## 10. Testing Requirements

- One test per matrix cell
- Unknown-action denial
- Cross-tenant negative paths
- Guard coverage on every protected route
