## 1. Epic Objective

Build the three non-manual import paths, each fully functional on the platforms where it exists.

---

## 2. Business Value

Blueprint §29.0 records that the Contact Picker API is Chromium/Android only — the designer brief's primary path simply does not exist for roughly half the target audience. This epic is where that gap is closed properly instead of apologised for.

---

## 3. User Stories

> **As a** Android user
> **I want** to pick people from my contacts
> **So that** setup takes seconds

> **As a** iPhone user
> **I want** a path that is as good as the Android one
> **So that** I am not treated as a second-class case

> **As a** user
> **I want** to let my family fill in their own details
> **So that** the information is right and stays right

---

## 4. Functional Requirements

- Contact Picker with a permission primer
- vCard/CSV upload with a per-row validation report
- Invite link with a public self-fill page

---

## 5. Technical Requirements

- Feature detection before rendering the picker option
- Streaming parse for large files
- Hashed single-use tokens

---

## 6. UI Requirements

- Four paths presented as equals
- Permission primer before the OS prompt
- Mapping preview with per-row status

---

## 7. API Requirements

_No new API surface in this epic._

---

## 8. Database Requirements

_No schema changes._

---

## 9. Security Requirements

- The public self-fill page discloses only the owner's display name
- Token hashed, expiring, single-use

---

## 10. Testing Requirements
